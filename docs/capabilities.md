# Decision-model capability matrix

Status checked against System1-Agents `3a2c2c66354c8ce587797d3e9e831db83abdaeb4` (2026-10-09). This page records what the code registers separately from what the repository has actually validated. A registration or contract test establishes adapter behavior, not model quality, an application success rate, or support on every device accepted by a loader.

For issue trackers and serving support, see [System1-Omni model tracker #83](https://github.com/ThinkFlowLab/system1-omni/issues/83) and its [supported models and hardware](https://github.com/ThinkFlowLab/system1-omni/blob/main/docs/supported-models.md). Omni owns model loading and accelerator execution; Agents owns the decision adapter and agent/application behavior. Omni support alone does not validate an Agents combination.

## Updating the matrix

For an implementation update, cite the current registration and contract tests, then list modality, supported question types, front/scenario, and serving path. For a validation update, add the exact Agents and Omni revisions, model and checkpoint revision, input/question scope, scenario and result, worker/frontend, device, and linked run artifacts. Label historical, replayed, stubbed, failed, and incomplete runs as such. Do not infer the served checkpoint from an adapter name, infer device validation from code support, or turn one run into a rate or performance claim.
